 ## ASCII 码
我们知道,计算机内部,所有信息最终都是一个二进制值。每一个二进制位(bit)有0和1两种状态,因此八个二进制位就可以组合出256种状态
这被称为一个字节(byte)。也就是说,一个字节一共可以用来表示256种不同的状态,每一个状态对应一个符号,就是256个符号,从00000000到11111111。

上个世纪60年代,美国制定了一套字符编码，对英语字符与二进制位之间的关系，做了统一规定。这被称为 ASCII 码，一直沿用至今。
ASCII 码一共规定了128个字符的编码,
比如空格SPACE是32(二进制00100000),大写的字母A是65(二进制01000001)。这128个符号(包括32个不能打印出来的控制符号),只占用了一个字节的后面7位,最前面的一位统一规定为0。

  ## AES（Advanced Encryption Standard）
-
  ### 简介
- 简介：现代主流分组密码，分组大小 128 位，密钥长度可为 128/192/256 位。安全性与性能兼备，广泛用于 TLS、磁盘加密、应用数据保护。
- 常用模式：GCM/CCM（AEAD，机密性+完整性）、CTR（需唯一 nonce）、CBC（需随机 IV 与正确填充，非 AEAD）。禁止使用 ECB。
- 安全性：在正确选择模式与参数、确保唯一 nonce/IV 的前提下被广泛认为安全。优先使用 AEAD（如 AES-GCM）。
- 适用场景：通用数据加密、网络通信、数据库字段加密、文件加密等。

  ### 示例（Node.js，AES-GCM）：
```js
const crypto = require('crypto')
const key = crypto.randomBytes(32)
const nonce = crypto.randomBytes(12)
const cipher = crypto.createCipheriv('aes-256-gcm', key, nonce)
const ciphertext = Buffer.concat([cipher.update(Buffer.from('hello aes gcm')), cipher.final()])
const tag = cipher.getAuthTag()

const decipher = crypto.createDecipheriv('aes-256-gcm', key, nonce)
decipher.setAuthTag(tag)
const plaintext = Buffer.concat([decipher.update(ciphertext), decipher.final()])

``` 
eg:数据加密：

  ## DES（Data Encryption Standard）

- 简介：老牌分组密码，分组大小 64 位，名义密钥 64 位但有效强度仅 56 位。
- 安全性：已不安全，暴力破解可行；在新设计中不应使用。历史兼容可考虑 3DES，但也已被弃用。
- 常用模式（仅历史兼容）：CBC/CTR 等；避免 ECB。
- 适用场景：仅限极端历史系统兼容；新系统请迁移至 AES/ChaCha20-Poly1305。

示例（Node.js，DES-CBC，演示用途，可能依赖 OpenSSL 构建）：

```js
const crypto = require('crypto')
const key = crypto.randomBytes(8)
const iv = crypto.randomBytes(8)
const cipher = crypto.createCipheriv('des-cbc', key, iv)
const ciphertext = Buffer.concat([cipher.update(Buffer.from('hello des')), cipher.final()])

const decipher = crypto.createDecipheriv('des-cbc', key, iv)
const plaintext = Buffer.concat([decipher.update(ciphertext), decipher.final()])
```

## Camellia

- 简介：分组大小 128 位，密钥长度 128/192/256 位；在安全性与性能上与 AES 可比，在部分地区与标准中被广泛采用。
- 常用模式：CBC/CTR（需随机 IV 或唯一 nonce）、CFB/OFB。使用 AEAD（如与额外 MAC 组合）可获得完整性保证。
- 安全性：公开分析良好，在正确参数与模式下被认为安全。
- 适用场景：对 AES 之外的替代需求；在不具备 AES 硬件加速但实现支持 Camellia 的环境中可选。

示例（Node.js，Camellia-CBC，支持与否取决于 OpenSSL）：

```js
const crypto = require('crypto')
const key = crypto.randomBytes(16)
const iv = crypto.randomBytes(16)
const cipher = crypto.createCipheriv('camellia-128-cbc', key, iv)
const ciphertext = Buffer.concat([cipher.update(Buffer.from('hello camellia')), cipher.final()])

const decipher = crypto.createDecipheriv('camellia-128-cbc', key, iv)
const plaintext = Buffer.concat([decipher.update(ciphertext), decipher.final()])
```


# 非对称加密

- 概念：使用公钥加密、私钥解密；或私钥签名、公钥验证。常用于密钥交换、数字签名与身份认证。
- 代表算法：RSA、ECC（如 ECDH/ECDSA）、ElGamal 等。实际业务多采用“混合加密”（非对称加密随机对称密钥，数据用对称加密）。
- 参数建议：RSA ≥ 2048 位；ECC 常用 `prime256v1`/`secp256k1`。避免 RSA-1024。

 ## RSA（加密/解密，OAEP）

```js
const crypto = require('crypto')
const { publicKey, privateKey } = crypto.generateKeyPairSync('rsa', { modulusLength: 2048 })
const ciphertext = crypto.publicEncrypt({ key: publicKey, padding: crypto.constants.RSA_PKCS1_OAEP_PADDING, oaepHash: 'sha256' }, Buffer.from('hello rsa'))
const plaintext = crypto.privateDecrypt({ key: privateKey, padding: crypto.constants.RSA_PKCS1_OAEP_PADDING, oaepHash: 'sha256' }, ciphertext)
```

## RSA（签名/验证，PSS 或 PKCS#1 v1.5）

```js
const crypto = require('crypto')
const { publicKey, privateKey } = crypto.generateKeyPairSync('rsa', { modulusLength: 2048 })
const sign = crypto.createSign('sha256')
sign.update('hello sign')
const signature = sign.sign(privateKey)
const verify = crypto.createVerify('sha256')
verify.update('hello sign')
const ok = verify.verify(publicKey, signature)
```

## ECDH（密钥协商）+ AES-GCM（混合加密）

```js
const crypto = require('crypto')
const alice = crypto.createECDH('prime256v1')
alice.generateKeys()
const bob = crypto.createECDH('prime256v1')
bob.generateKeys()
const secretA = alice.computeSecret(bob.getPublicKey())
const key = crypto.createHash('sha256').update(secretA).digest()
const nonce = crypto.randomBytes(12)
const cipher = crypto.createCipheriv('aes-256-gcm', key, nonce)
const ciphertext = Buffer.concat([cipher.update(Buffer.from('hello ecdh')), cipher.final()])
const tag = cipher.getAuthTag()
const decipher = crypto.createDecipheriv('aes-256-gcm', key, nonce)
decipher.setAuthTag(tag)
const plaintext = Buffer.concat([decipher.update(ciphertext), decipher.final()])
```

## 使用要点（非对称）

- 不直接用 RSA 加密大数据：最大明文受密钥长度与填充限制；采用混合加密。
- 选择现代填充：加密优先 OAEP；签名优先 PSS 或 ECDSA。
- 密钥管理：妥善保护私钥，必要时使用硬件保管（HSM/TPM）。
- 曲线与参数：统一曲线与编码格式，避免互操作问题。

# 摘要算法

- 定义：将任意长度数据映射为固定长度输出的单向函数，用于完整性校验、消息摘要与指纹。
- 安全性：避免使用 MD5、SHA-1；优先 SHA-256/512、SHA3-256/512、BLAKE2b/BLAKE2s。BLAKE3 与 SM3 支持取决于环境或库。
- 典型用途：校验下载文件、数字签名中的消息摘要、内容寻址、去重比较。

 ## 常见摘要算法算法
- MD5：存在碰撞攻击，已不安全。 （生成固定的32位16进制字符串。）
- SHA-1：存在实用碰撞，已不安全。（40bd001563085fc35165329ea1ff5c5ecbdbbeef 是一个40位的16进制字符串。）
- SHA-2：SHA-256、SHA-512 等，当前主流安全选择。 (a665a45920422f9d417e4867efdc4fb8a04a1f3fff1fa07e998e86f7f7a27ae3 是一个64位的16进制字符串。)
- SHA-512 3c9909afec25354d551dae21590bb26e38d53f2173b8d3dc3eee4c047e7ab1c1eb8b85103e3be7ba613b31bb5c9c36214dc9f14a42fd7a2fdb84856bca5c44c2 (是一个64位的16进制字符串。)
- SHA-3：Keccak 家族，抗故障设计，性能随实现不同。
- BLAKE2：`blake2b512`、`blake2s256`，高性能、广泛应用，Node 支持取决于 OpenSSL。
- BLAKE3：更高性能，需第三方库。
- SM3：国密摘要算法，支持取决于 OpenSSL 构建与 Node 版本。

### 密码存储与密钥派生

- 不要使用 MD5、SHA-1 或直接 SHA-256 存密码。
- 使用专用 KDF 或密码哈希：`bcrypt`、`scrypt`、`Argon2`，包含盐与成本因子。
- Node 原生可用 `crypto.scryptSync` 做密钥派生，或选用成熟库管理密码存储。
